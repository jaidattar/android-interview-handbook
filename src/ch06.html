The seven-step coding-round routine

  1. Clarify: input size, duplicates, negatives, empty input, whether it is sorted, one answer or all answers, and whether you may modify the input.
  2. Examples: walk through one normal case and one edge case by hand.
  3. Brute force first, and state its complexity: “The naive way is O(n²). Let me see if I can do better.”
  4. Optimise: name the pattern (hash map, two pointers, window and so on) and explain why it applies.
  5. Code cleanly, with meaningful names, while you talk.
  6. Test by dry-running your example and the edge cases.
  7. State time and space complexity, then mention alternatives and follow-ups.

Kotlin tips: use ArrayDeque from kotlin.collections for stacks and queues instead of the legacy java.util.Stack. IntArray(26) counts letters. mid = lo + (hi - lo) / 2 avoids overflow. Char - Char gives an Int. Avoid !!. Watch Int overflow, and use Long when sums can be large.

1. Arrays and strings: Two Sum

Core pattern. Cue: “find two numbers that add to a target”.

Approach

The brute force uses two nested loops and costs O(n²). Better: for each number, ask “have I already seen target minus x?” A HashMap from value to index answers that in O(1), so one pass is enough.

fun twoSum(nums: IntArray, target: Int): IntArray {
    val seen = HashMap<Int, Int>()                      // value -> index
    for (i in nums.indices) {
        val need = target - nums[i]
        seen[need]?.let { return intArrayOf(it, i) }      // check BEFORE inserting
        seen[nums[i]] = i
    }
    return intArrayOf()                                    // or throw if a solution is guaranteed
}

Time O(n), space O(n). Checking before inserting means an element is never paired with itself.

Edge cases: duplicates such as [3, 3] with target 6, negatives, no solution, empty array. Follow-ups: if the input is already sorted, use two pointers in O(1) space. Return all pairs. 3Sum is sort plus two pointers. Strings are immutable in Kotlin, so use buildString inside loops.

2. HashMap and HashSet: First non-repeating character

Cue: “count occurrences”, “have I seen this?”.

Approach

Two passes: count every character, then return the first index whose count is 1. The second pass runs in original order, which is what makes “first” correct.

fun firstUniqChar(s: String): Int {
    val count = HashMap<Char, Int>()
    for (c in s) count[c] = (count[c] ?: 0) + 1
    for (i in s.indices) if (count[s[i]] == 1) return i
    return -1
}
// Lowercase letters only: val count = IntArray(26); count[c - 'a']++   (no hashing, O(1) space)

Time O(n), space O(k), where k is the number of distinct characters. It is O(1) when the alphabet is fixed.

Quick HashSet wins

fun containsDuplicate(nums: IntArray) = nums.toHashSet().size != nums.size
// Group anagrams: key = word.toCharArray().sorted().joinToString(""), then map key to list

Edge cases: an empty string returns -1, and so does a string where every character repeats. State your alphabet assumption for Unicode or uppercase. Follow-ups: streaming input (a LinkedHashMap keeps order). Explain that HashMap is O(1) on average, and why. See Chapter {{ch:1}} for the internals.

3. Two pointers: Valid palindrome

Cue: sorted input, symmetric check, “in place”, “O(1) extra space”.

Approach

Put one pointer at each end and move them inward. Skip characters that do not count, then compare. Each pointer moves at most n times, so this is O(n) time and O(1) space, compared with O(n) space for building a reversed copy.

fun isPalindrome(s: String): Boolean {
    var l = 0
    var r = s.lastIndex
    while (l < r) {
        while (l < r && !s[l].isLetterOrDigit()) l++
        while (l < r && !s[r].isLetterOrDigit()) r--
        if (s[l].lowercaseChar() != s[r].lowercaseChar()) return false
        l++; r--
    }
    return true
}

Edge cases: an empty string or a single character returns true. A string of only punctuation returns true. Mixed case. Follow-ups: Valid Palindrome II, where one character may be deleted; Two Sum II on a sorted array; Container With Most Water; removing duplicates in place with slow and fast pointers.

4. Sliding window: Longest substring without repeating characters

Cue: the longest or shortest contiguous range that satisfies a constraint.

Approach

Keep a window [left, right] with no duplicates. Move right forward. If the new character was last seen inside the window, move left to just after that earlier position. Track the largest window length.

fun lengthOfLongestSubstring(s: String): Int {
    val lastSeen = HashMap<Char, Int>()
    var left = 0
    var best = 0
    for (right in s.indices) {
        val c = s[right]
        val prev = lastSeen[c]
        if (prev != null && prev >= left) left = prev + 1    // prev >= left: it is inside the window
        lastSeen[c] = right
        best = maxOf(best, right - left + 1)
    }
    return best
}

Time O(n), since each index is visited once. Space O(k). The classic bug is “abba”: without the check prev >= left, left would move backwards.

Template: expand right, shrink left while the window is invalid, then update the answer. Follow-ups: Best Time to Buy and Sell Stock, Longest Repeating Character Replacement, Minimum Window Substring, and the maximum sum of a fixed-size window.

5. Stack and queue: Valid parentheses

Cue: nesting, matching pairs, “the most recent unresolved item”.

Approach

Push every opening bracket. On a closing bracket, the top of the stack must be its matching opener, and you pop it. At the end the stack must be empty.

fun isValid(s: String): Boolean {
    val stack = ArrayDeque<Char>()
    val match = mapOf(')' to '(', ']' to '[', '}' to '{')
    for (c in s) {
        if (c in match) {
            if (stack.removeLastOrNull() != match[c]) return false   // empty stack or wrong opener
        } else {
            stack.addLast(c)
        }
    }
    return stack.isEmpty()
}

Time O(n), space O(n). A queue is FIFO: addLast and removeFirst. It drives BFS in topic 8.

Edge cases: an empty string is valid. A string of only closers is invalid, which removeLastOrNull handles. Leftover openers are invalid. An odd length allows a quick early exit. Follow-ups: Min Stack, Daily Temperatures with a monotonic stack, evaluating reverse Polish notation, and implementing a queue with two stacks.

6. Binary search: Search in a sorted array

Cue: sorted data, or “find the smallest value that satisfies a condition”.

Approach

Halve the search range each step, which gives O(log n). Decide on the invariant, here the inclusive range [lo, hi], and keep it consistent.

fun search(nums: IntArray, target: Int): Int {
    var lo = 0
    var hi = nums.lastIndex
    while (lo <= hi) {
        val mid = lo + (hi - lo) / 2            // avoids Int overflow
        when {
            nums[mid] == target -> return mid
            nums[mid] < target  -> lo = mid + 1
            else                -> hi = mid - 1
        }
    }
    return -1
}

Time O(log n), space O(1). Kotlin also has nums.binarySearch(target), which returns -(insertionPoint) - 1 when the value is absent.

Bugs to avoid: infinite loops from wrong updates to lo and hi, and off-by-one errors between < and <=. Follow-ups: first and last occurrence (lower and upper bound), Search in a Rotated Sorted Array, Find Peak Element, Sqrt(x), and binary search on the answer, such as the minimum capacity to ship everything in D days.

7. Sorting: Merge intervals

Cue: overlapping ranges, where ordering must come before scanning.

Approach

Sort by start. Then scan once: if the next interval starts before or at the current end, extend the end; otherwise start a new interval.

fun merge(intervals: Array<IntArray>): Array<IntArray> {
    if (intervals.isEmpty()) return emptyArray()
    val sorted = intervals.sortedBy { it[0] }
    val result = mutableListOf(sorted[0].copyOf())
    for (i in 1 until sorted.size) {
        val last = result.last()
        if (sorted[i][0] <= last[1]) last[1] = maxOf(last[1], sorted[i][1])
        else result.add(sorted[i].copyOf())
    }
    return result.toTypedArray()
}

Time O(n log n), dominated by the sort. Space O(n). maxOf handles containment, such as [1, 10] and [2, 3].

What should you know about sorting itself?

  • Merge sort: O(n log n) always, stable, O(n) extra space. Quick sort: O(n log n) on average, O(n²) in the worst case, in place. Heap sort: O(n log n), O(1) extra space.
  • On the JVM, primitive arrays use dual-pivot quicksort, and object collections use TimSort, which is stable. So sortedBy keeps ties in their original order.

Edge cases: touching intervals such as [1, 2] and [2, 3] should merge, so use <=. Also check a single interval, unsorted input, and identical intervals. Follow-ups: Insert Interval, Meeting Rooms I and II, and Non-overlapping Intervals.

8. Trees: Binary tree traversal

Cue: a hierarchy, “visit every node”, questions about depth, paths or ancestors.

The four traversals

  • Preorder (node, left, right), inorder (left, node, right; the inorder traversal of a BST is sorted), postorder (left, right, node), and level order (BFS with a queue).
class TreeNode(val value: Int, var left: TreeNode? = null, var right: TreeNode? = null)

fun inorder(root: TreeNode?, out: MutableList<Int> = mutableListOf()): List<Int> {
    if (root == null) return out                                 // base case
    inorder(root.left, out)
    out.add(root.value)
    inorder(root.right, out)
    return out
}

fun inorderIterative(root: TreeNode?): List<Int> {          // explicit stack, no recursion depth risk
    val result = mutableListOf<Int>()
    val stack = ArrayDeque<TreeNode>()
    var current = root
    while (current != null || stack.isNotEmpty()) {
        while (current != null) { stack.addLast(current); current = current.left }
        val node = stack.removeLast()
        result.add(node.value)
        current = node.right
    }
    return result
}

fun levelOrder(root: TreeNode?): List<List<Int>> {
    val result = mutableListOf<List<Int>>()
    if (root == null) return result
    val queue = ArrayDeque<TreeNode>().apply { addLast(root) }
    while (queue.isNotEmpty()) {
        val level = mutableListOf<Int>()
        repeat(queue.size) {
            val node = queue.removeFirst()
            level.add(node.value)
            node.left?.let(queue::addLast)
            node.right?.let(queue::addLast)
        }
        result.add(level)
    }
    return result
}

Time O(n) for all of them. Space O(h) for DFS, where h is the height (O(n) for a skewed tree), and O(w) for BFS, where w is the maximum width.

Follow-ups: Maximum Depth, which is 1 + max(depth(left), depth(right)). Validate BST, by passing min and max bounds down. Lowest Common Ancestor, Invert Tree, Path Sum. Recursion on a very deep tree can hit StackOverflowError.

9. Recursion basics

Cue: the problem contains a smaller version of itself.

The recipe

  1. Base case, which stops the recursion.
  2. Recursive case, which moves toward the base case.
  3. Trust the smaller call. Assume it returns the right answer, then combine.
fun factorial(n: Int): Long = if (n <= 1) 1L else n * factorial(n - 1)

// Naive Fibonacci is O(2^n). Memoisation makes it O(n).
fun fib(n: Int, memo: HashMap<Int, Long> = HashMap()): Long {
    if (n <= 1) return n.toLong()
    return memo.getOrPut(n) { fib(n - 1, memo) + fib(n - 2, memo) }
}

tailrec fun sumTo(n: Int, acc: Long = 0): Long =
    if (n == 0) acc else sumTo(n - 1, acc + n)     // compiled into a loop

// Backtracking: choose, explore, then undo the choice
fun subsets(nums: IntArray): List<List<Int>> {
    val result = mutableListOf<List<Int>>()
    val path = mutableListOf<Int>()
    fun go(i: Int) {
        if (i == nums.size) { result.add(path.toList()); return }
        go(i + 1)                                    // skip nums[i]
        path.add(nums[i]); go(i + 1); path.removeLast()   // take it, then undo
    }
    go(0)
    return result
}

“Each call uses a stack frame, so depth matters: the space cost is O(depth), and very deep recursion can overflow the stack.”

Note: tailrec works only when the self-call is the last operation. Practise: reversing a string or list, computing power(x, n) in O(log n), generating parentheses, permutations, Fibonacci, and flattening a nested list.

10. Dynamic programming: Climbing stairs

Cue: overlapping subproblems, “how many ways”, “minimum or maximum cost”.

The DP recipe

  1. State: ways(i) is the number of ways to reach step i.
  2. Recurrence: you arrive from step i-1 or i-2, so ways(i) = ways(i-1) + ways(i-2). It is Fibonacci.
  3. Base cases: ways(1) = 1, ways(2) = 2.
  4. Order and space: only the last two values are needed, so the space is O(1).
fun climbStairs(n: Int): Int {
    if (n <= 2) return n
    var prev2 = 1      // ways(i-2)
    var prev1 = 2      // ways(i-1)
    for (i in 3..n) {
        val current = prev1 + prev2
        prev2 = prev1
        prev1 = current
    }
    return prev1
}

Time O(n), space O(1). Show the evolution in an interview: plain recursion O(2ⁿ), then top-down memoisation with O(n) space, then a bottom-up table, then two variables with O(1) space.

Edge cases: n = 1 and n = 2. Large n overflows Int, so use Long or BigInteger if asked. Follow-ups, roughly by difficulty: Min Cost Climbing Stairs, House Robber, Coin Change, Longest Increasing Subsequence, Unique Paths, and 0/1 Knapsack.
