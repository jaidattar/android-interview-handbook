1. val vs var

Often asked as: “Is val immutable?”, “val vs const val”, “lateinit vs lazy”.

Is val immutable?

No. val is a read-only reference, not an immutable object. val list = mutableListOf(1) can still be mutated. In bytecode, a val is a private final field plus a getter; a var adds a setter. A val with a custom getter has no backing field and is recomputed on every access.

val vs const val?

const val is a compile-time constant. It must be a primitive or String, declared at top level or inside an object or companion object, and it is inlined at call sites. A plain val is initialised at runtime. Use const for annotation arguments and when branch labels.

lateinit vs by lazy?

  • lateinit var: mutable, non-null, not for primitives. Reading it too early throws UninitializedPropertyAccessException. Check with ::x.isInitialized. Typical use: dependency injection and view binding.
  • by lazy: val only, computed once on first access, thread-safe by default. Modes: SYNCHRONIZED (default), PUBLICATION, and NONE (fastest, single-thread only).
val a = listOf(1)              // read-only reference
var b = listOf(1)              // reference can be reassigned
const val TAG = "Main"         // compile-time constant
val heavy by lazy { parse() }  // computed once, on first use

Trap: smart casts work on local vals, but not on var properties (they could change between the check and the use), on val properties with a custom getter, or on properties from another module.

2. == vs ===

Often asked as: “Structural vs referential equality”, “the Integer cache puzzle”, “the equals and hashCode contract”.

What is the difference?

== is structural equality. It compiles to a null-safe call to equals(). === is referential equality: it checks whether both sides are the same object. For primitives the two behave the same.

What does this print?

val a: Int? = 127; val b: Int? = 127
println(a === b)   // true  (boxed Integer cache covers -128..127)
val c: Int? = 1000; val d: Int? = 1000
println(c === d)   // false (two separate boxed objects)
println(c == d)    // true

Never use === on boxed numbers. Kotlin warns about it for good reason.

Is there a Double edge case?

When the static type is Double, == follows IEEE 754: NaN == NaN is false and 0.0 == -0.0 is true. When the static type is Any, Comparable or a generic, it uses equals(), where NaN equals NaN and 0.0 does not equal -0.0.

Follow-up: if you override equals you must override hashCode too (equal objects must have equal hashes), or HashMap and HashSet lookups fail. Data classes do both for you.

3. Data classes and sealed classes

Often asked as: “When do you use a data class vs a sealed class?”, “Modelling UI state”, “sealed vs enum”.

What does a data class generate?

equals, hashCode, toString, copy and componentN, all from primary-constructor properties only. Body properties are ignored. It needs at least one val or var parameter and cannot be open, abstract, sealed or inner. copy() is shallow: nested mutable objects are shared between copies.

What is a sealed class and why use one?

A restricted hierarchy: all direct subclasses are known at compile time, in the same package and module. A when over it is exhaustive without else, and adding a new subtype breaks the build wherever it is not handled. Prefer sealed interface when subtypes need other parents, and data object for stateless cases.

sealed interface UiState {
    data object Loading : UiState
    data class Success(val items: List<Item>) : UiState
    data class Error(val message: String) : UiState
}

fun render(state: UiState) = when (state) {
    UiState.Loading      -> showSpinner()
    is UiState.Success   -> showList(state.items)
    is UiState.Error     -> showError(state.message)
}

Sealed or enum?

An enum is a fixed set of single instances that all share the same shape. A sealed hierarchy is a fixed set of types, each able to carry different state, with many instances.

Trap: a mutable var inside a data class used as a HashMap or HashSet key changes its hash after insertion, and the entry becomes unreachable. Arrays inside data classes compare by reference. In Compose, unstable types such as List cause extra recomposition; see Chapter {{ch:4}}.

4. inline, noinline and crossinline

Often asked as: “Why does inline exist?”, “non-local return”, “reified types”. A favourite senior-level question.

What does inline do?

The compiler copies the function body and each lambda body into the call site. That avoids allocating a Function object, avoids a virtual call, and allows a non-local return from the lambda. The cost is bytecode size, so use it for small functions that take lambdas, such as let, run, apply, repeat and measureTimeMillis.

noinline vs crossinline?

  • noinline: this lambda parameter is not inlined, so you can store it or pass it to a non-inline function.
  • crossinline: the lambda is inlined, but a non-local return is forbidden. You need it when the lambda runs inside another context, such as a Runnable or an object expression, where a return would be illegal.
inline fun runTwice(
    a: () -> Unit,                     // inlined
    noinline b: () -> Unit,            // kept as an object, can be stored
    crossinline c: () -> Unit          // inlined, but no 'return' inside
) {
    val r = Runnable { c() }             // why crossinline is required here
    saved = b
}

inline fun <reified T> String.parseAs(): T = Json.decodeFromString(this)

Follow-up: reified type parameters work only in inline functions, because the type is substituted at each call site, which avoids type erasure. A public inline function cannot touch non-public API unless it is marked @PublishedApi. Inlining a function with no lambda parameters gives little benefit, and the compiler warns about it.

5. Extension functions

Often asked as: “How are they compiled?”, “Can you override them?”, “member vs extension”.

How do they work?

They compile to static methods that take the receiver as the first parameter. For example, fun View.gone() becomes ViewKt.gone(View). They do not modify the class, and they cannot access private or protected members.

Are they polymorphic?

No. They are resolved by the declared type, not the runtime type. A member always wins over an extension with the same signature.

open class A
class B : A()
fun A.hi() = "A"
fun B.hi() = "B"
val x: A = B()
println(x.hi())   // prints "A": static dispatch on the declared type

Other facts worth knowing

  • Extension properties have no backing field, only a getter and an optional setter.
  • The receiver can be nullable: fun String?.orEmpty().
  • Scope follows imports, so put Android helpers such as Context.dp or View.show() in focused files.

Trap: extensions on Any or String clutter autocomplete for the whole team. They are also hard to mock in unit tests, where mockkStatic may be needed.

6. Higher-order functions and lambdas

Often asked as: “What are function types under the hood?”, “closures and leaks”, “scope functions”, “DSLs”.

What is a higher-order function?

A function that takes or returns another function. A function type such as (Int) -> String compiles to the interface Function1<Int, String>. A non-inline lambda is an object. A capturing lambda allocates on each creation; a non-capturing lambda is a singleton.

What is a closure?

A lambda that captures variables from its enclosing scope. Captured vars are wrapped in a Ref object so they can be changed. Android leak risk: a long-lived lambda that captures an Activity or View keeps it alive.

Trap: a plain return inside a non-inline lambda is illegal; use a labelled return such as return@forEach. Inside an inline lambda, a plain return exits the enclosing function.

7. Null safety

Often asked as: “Platform types”, “Why is !! a smell?”, “How can an NPE still happen in Kotlin?”.

How does Kotlin handle null?

Nullability is part of the type system: String and String? are different types. The main tools are ?., ?:, ?.let, as?, smart casts, and requireNotNull or checkNotNull. The compiler inserts parameter null checks into public functions.

How can an NPE still happen?

  • !!, or a lateinit read before initialisation.
  • Platform types (String!) from Java code without nullability annotations: the compiler trusts you.
  • Reflection and serialisation (Gson, Parcel, reflection-based libraries) can put null into non-null fields, bypassing constructor defaults.
  • Calling an overridable member from a constructor, before the subclass has initialised its fields.
val len = name?.length ?: 0
user?.let { show(it) } ?: showEmpty()
fun fail(message: String): Nothing = throw IllegalStateException(message)
val id = intent.getStringExtra("id") ?: error("id is required")

Follow-up: Nothing is the bottom type, a function that never returns. Unit is a real singleton object. Prefer ?: error("…") over !! so a crash carries a useful message.

8. Collections: List, Set and Map

Often asked as: “Read-only vs immutable”, “Which implementation backs listOf?”, “Sequence vs List”.

What are the differences?

  • List: ordered and indexed, duplicates allowed. ArrayList gives O(1) index access.
  • Set: unique elements with no index. HashSet is unordered, LinkedHashSet keeps insertion order, TreeSet is sorted in O(log n).
  • Map: unique keys mapped to values. HashMap is O(1) on average, LinkedHashMap keeps insertion order, TreeMap is sorted. A Map is not a Collection.

Read-only or immutable?

List is a read-only view, not an immutable collection. Another reference to the same MutableList can still change it, and a cast can expose that. listOf() returns a read-only implementation, and setOf and mapOf return the Linked versions so order is kept. For guaranteed immutability use kotlinx.collections.immutable, which also helps Compose stability.

Collection or Sequence?

Collection operators are eager: each step builds an intermediate list. asSequence() is lazy, and each element flows through the whole chain. Sequences help with large data and short-circuit operations like first, and they can be slower for small lists.

Trap: modifying a collection while iterating over it throws ConcurrentModificationException. Use removeAll or an iterator's remove. On Android, ArrayMap and SparseArray save memory for small maps with primitive keys.

9. How HashMap works internally

Often asked as: “Walk me through put and get”, “collisions”, “resizing”, “HashMap vs ConcurrentHashMap”. Almost guaranteed to come up.

How does put(k, v) work?

  1. Compute h = key.hashCode() ^ (h >>> 16) to spread the high bits.
  2. Index = (n - 1) and hash. The capacity n is always a power of two, which makes this faster than modulo.
  3. If the bucket is empty, create a node. Otherwise compare the hash first, then == / equals(). If the key matches, replace the value; if not, append to the chain (a collision).
  4. A bucket with 8 or more nodes, in a table of at least 64, becomes a red-black tree (O(log n)). It turns back into a list at 6 or fewer.
  5. If size exceeds capacity × load factor (16 × 0.75 = 12), the table doubles and nodes are redistributed.

How does get(k) work, and is a null key allowed?

The lookup uses the same hash, goes to the same index, checks the first node, then walks the chain or tree using equals. A null key is allowed and always goes to bucket 0. The average cost is O(1), and the worst case is O(log n) since Java 8 (O(n) before).

Is HashMap thread-safe?

No. Concurrent writes lose updates and cause visibility problems. Before Java 8 a concurrent resize could even loop forever. ConcurrentHashMap uses compare-and-set for empty buckets, locks only the bucket head for other writes, allows lock-free reads, and rejects null keys and values.

Trap: mutating a key after insertion, or overriding equals without hashCode, makes the entry unreachable. Set an initial capacity of about expected / 0.75 + 1 to avoid repeated resizes.

10. Java concurrency vs Kotlin coroutines

Often asked as: “Why coroutines over threads?”, “structured concurrency”, “cancellation”, “how is suspend compiled?”.

What is the core difference?

A thread is an OS resource, with a stack of roughly 1 MB and a costly context switch. Blocking a thread wastes it. A coroutine is a lightweight, suspendable computation that runs on a small thread pool. suspend frees the thread instead of blocking it, so you can run 100,000 coroutines, but not 100,000 threads.

How is suspend implemented?

The compiler performs a continuation-passing transformation. It adds a hidden Continuation parameter and turns the function into a state machine, where each suspension point is a numbered state and local variables live in the continuation object. Resuming means calling continuation.resumeWith(result).

What is structured concurrency?

Coroutines live inside a scope with a parent-child Job tree. The parent waits for its children, cancelling the parent cancels all children, and a child failure cancels the parent, unless you use SupervisorJob or supervisorScope. Nothing is leaked, unlike a forgotten Thread or Executor task. Android provides viewModelScope and lifecycleScope, and you should avoid GlobalScope.
